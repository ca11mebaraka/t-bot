## Введение

Бот поддерживает **несколько стратегий одновременно** для каждого инструмента. Каждая стратегия независимо анализирует поток цен и генерирует сигналы BUY / SELL. Сигнал любой стратегии немедленно исполняется.

> **Важно:** Стратегии являются упрощёнными техническими индикаторами. Они не учитывают фундаментальный анализ, новостной фон и макроэкономические факторы. Перед использованием в production обязательно тестируйте в sandbox-режиме.

## Общая архитектура стратегий

```python
class BaseStrategy(ABC):
    instrument_id: str           # FIGI инструмента

    def update(price, volume=0) -> Optional[Signal]:
        # Принимает новую цену (и опционально объём)
        # Обновляет внутреннее состояние (буферы, счётчики)
        # Возвращает Signal или None

class Signal:
    type: SignalType    # BUY | SELL | HOLD
    instrument_id: str
    price: Decimal      # цена в момент сигнала
    reason: str         # объяснение: "MA9 пересекла MA21 снизу"
```

`update()` вызывается **на каждом тике** (цикл `trader.py`). Стратегия сама накапливает историю внутри себя и выдаёт сигнал только при выполнении условий.

## MA Crossover

**Файл:** `strategies/ma_crossover.py`  
**Класс:** `MACrossoverStrategy(instrument_id, short_period=9, long_period=21)`

### Теория

Простая скользящая средняя (SMA) сглаживает ценовые данные, усредняя цены за последние N периодов. Две SMA с разными периодами позволяют определить направление тренда:

- **Быстрая MA** (короткий период) — реагирует быстро, больше шума
- **Медленная MA** (длинный период) — реагирует медленно, отражает общий тренд

```
SMA(n) = (P₁ + P₂ + ... + Pₙ) / n
```

### Сигналы

| Событие | Сигнал | Интерпретация |
|---|---|---|
| Быстрая MA пересекает медленную **снизу вверх** | **BUY** | Краткосрочный импульс разворачивается вверх, начало восходящего тренда |
| Быстрая MA пересекает медленную **сверху вниз** | **SELL** | Краткосрочный импульс разворачивается вниз, начало нисходящего тренда |

### Визуализация

```
Цена
 ▲
 │     ╭──╮           ← BUY (быстрая MA пересекла медленную снизу)
 │    ╱    ╲
 │───╱──────╲────╮    ← медленная MA (MA21)
 │  ╱        ╲  ╱
 │ ╱          ╲╱      ← быстрая MA (MA9)
 │╱                   ← SELL (быстрая MA пересекла медленную сверху)
 └──────────────────► t
```

### Параметры

| Параметр | .env | По умолчанию | Рекомендации |
|---|---|---|---|
| `short_period` | `MA_SHORT` | `9` | 5–20. Меньше → больше сигналов, больше ложных |
| `long_period` | `MA_LONG` | `21` | 20–50. Должен быть > short_period |

### Сильные стороны

- Хорошо работает на **трендовых рынках**
- Простота и надёжность — стратегия проверена десятилетиями
- Нет перегрузки параметрами

### Слабые стороны

- **Запаздывает** — сигнал приходит после начала движения
- Генерирует много **ложных сигналов** на боковом рынке (флэт)
- При маленьких периодах — высокая частота входов/выходов

### Пример работы

```
Период  Цена   MA9    MA21   Сигнал
   1    100.0    –      –
   ...
   9    108.0  103.2    –
   ...
  21    115.0  110.5  107.3
  22    117.0  111.8  107.9   BUY ← MA9 > MA21 впервые
  23    114.0  111.6  108.2
  ...
  35    105.0  108.9  109.1   SELL ← MA9 < MA21 впервые
```

## RSI

**Файл:** `strategies/rsi.py`  
**Класс:** `RSIStrategy(instrument_id, period=14, oversold=30, overbought=70)`

### Теория

RSI (Relative Strength Index) — осциллятор, измеряющий **силу и скорость ценовых движений**. Значение от 0 до 100.

```
RS  = среднее_роста(period) / среднее_падения(period)
RSI = 100 − 100 / (1 + RS)
```

- RSI > 70 → рынок **перекуплен** (возможна коррекция вниз)
- RSI < 30 → рынок **перепродан** (возможен отскок вверх)
- RSI ≈ 50 → нейтральная зона

### Сигналы

Бот генерирует сигнал **не при входе** в зону, а при **выходе** из неё — это фильтрует ложные срабатывания:

| Событие | Сигнал | Интерпретация |
|---|---|---|
| RSI выходит из зоны перепроданности (`prev ≤ 30` и `curr > 30`) | **BUY** | Давление продавцов иссякло, начинается восстановление |
| RSI выходит из зоны перекупленности (`prev ≥ 70` и `curr < 70`) | **SELL** | Давление покупателей иссякло, начинается коррекция |

### Визуализация

```
RSI
 ▲
100│
 70├──────────────────  ← overbought   SELL при выходе ↓
   │         ╭──╮
 50│───╮   ╭─╯  ╰─╮
   │   ╰───╯      │
 30├──────────────────  ← oversold     BUY при выходе ↑
   │              ╰─╮
  0│
   └──────────────────► t
```

### Параметры

| Параметр | .env | По умолчанию | Рекомендации |
|---|---|---|---|
| `period` | `RSI_PERIOD` | `14` | 7–21. Меньше → быстрее реагирует, больше шума |
| `oversold` | `RSI_OVERSOLD` | `30` | 20–35. Ниже → реже, но надёжнее сигналы |
| `overbought` | `RSI_OVERBOUGHT` | `70` | 65–80. Выше → реже, но надёжнее сигналы |

### Сильные стороны

- Хорошо работает на **боковых рынках** (флэт, коридор)
- Исторически надёжен на краткосрочных и среднесрочных горизонтах
- Даёт контекст о силе тренда

### Слабые стороны

- На **сильных трендах** RSI может долго оставаться в зоне перекупленности/перепроданности — сигналы запаздывают или отсутствуют
- Период (14) требует калибровки под конкретный инструмент и таймфрейм

### Пример работы

```
Период  Цена    RSI   Сигнал
  14    105.2  55.3
  15    100.1  42.1
  16     95.0  31.5
  17     93.0  28.2   ← вошли в зону перепроданности
  18     94.5  30.8   BUY ← RSI вышел из перепроданности (28.2 → 30.8)
  19     98.0  38.5
  ...
  40    130.0  72.1   ← вошли в зону перекупленности
  41    128.5  69.4   SELL ← RSI вышел из перекупленности (72.1 → 69.4)
```

## Как стратегии работают вместе

Для каждого инструмента создаётся **список стратегий**. Они работают независимо и каждая может выдать сигнал на одном и том же тике.

```
Тик: цена = 294.50 ₽
  MA Crossover → None  (условие не выполнено)
  RSI          → BUY   (RSI = 30.8, вышел из перепроданности)
                  └──► исполняется рыночная заявка BUY
```

**Потенциальный конфликт:** MA может выдать BUY, а RSI одновременно SELL. В текущей реализации исполняются **оба сигнала** подряд. Это ожидаемое поведение при использовании нескольких независимых стратегий.

Если вам нужна консенсусная логика (исполнять только если обе стратегии согласны), это требует изменения `trader.py::run_trading_loop`.

## Управление рисками

### Стоп-ордера (автоматические)

После каждой покупки в production-режиме автоматически выставляются:

| Ордер | Уровень | Действие |
|---|---|---|
| **Take-profit** | `цена_покупки × 1.05` (+5%) | Продать при росте |
| **Stop-loss** | `цена_покупки × 0.98` (−2%) | Продать при падении |

Уровни захардкожены в `client.py::place_stop_orders`. Чтобы изменить, отредактируйте параметры `take_profit_pct` и `stop_loss_pct`.

### Ограничение размера позиции

Параметр `MAX_LOTS` контролирует максимальное количество лотов в одной заявке. По умолчанию = 1.

> Бот не отслеживает суммарную открытую позицию. Если стратегия выдаёт несколько BUY-сигналов подряд, каждый из них будет исполнен. Это нормальное поведение для стратегий, ориентированных на усреднение.

### Режимы безопасности

| Режим | Команда | Описание |
|---|---|---|
| **Sandbox** | `TRADING_MODE=sandbox` | Виртуальные деньги, реальный API |
| **Dry-run** | `--dry-run` | Реальный API, только логирование сигналов |
| **Production** | `TRADING_MODE=production` | Реальные деньги и сделки |

**Рекомендуемый порядок тестирования:**
1. `--dry-run` — убедитесь, что сигналы генерируются правильно
2. `TRADING_MODE=sandbox` — проверьте исполнение заявок
3. `TRADING_MODE=production` — запуск с реальными деньгами

## Создание собственной стратегии

### Минимальная реализация

```python
# strategies/my_strategy.py
from collections import deque
from decimal import Decimal
from typing import Optional

from .base import BaseStrategy, Signal, SignalType


class BollingerBandsStrategy(BaseStrategy):
    """
    Пример: стратегия полос Боллинджера.
    BUY когда цена касается нижней полосы,
    SELL когда цена касается верхней.
    """

    def __init__(self, instrument_id: str, period: int = 20, std_dev: float = 2.0):
        super().__init__(instrument_id)
        self.period = period
        self.std_dev = std_dev
        self._prices: deque[Decimal] = deque(maxlen=period)

    @property
    def name(self) -> str:
        return f"BB({self.period},{self.std_dev})"

    def update(self, price: Decimal, volume: int = 0) -> Optional[Signal]:
        self._prices.append(price)
        if len(self._prices) < self.period:
            return None

        prices = list(self._prices)
        mean = sum(prices) / Decimal(self.period)
        variance = sum((p - mean) ** 2 for p in prices) / Decimal(self.period)
        std = variance.sqrt()

        upper = mean + Decimal(str(self.std_dev)) * std
        lower = mean - Decimal(str(self.std_dev)) * std

        if price <= lower:
            return Signal(
                type=SignalType.BUY,
                instrument_id=self.instrument_id,
                price=price,
                reason=f"Цена {price:.2f} ≤ нижней полосы {lower:.2f}",
            )
        if price >= upper:
            return Signal(
                type=SignalType.SELL,
                instrument_id=self.instrument_id,
                price=price,
                reason=f"Цена {price:.2f} ≥ верхней полосы {upper:.2f}",
            )
        return None
```

## Подбор параметров

### Общие принципы

- **Shorter ≠ better** — чем короче период индикатора, тем больше ложных сигналов
- **Оптимизация на истории** — подбор параметров по историческим данным легко приводит к overfitting. Всегда валидируйте на данных, которые не использовались при подборе
- **Разные инструменты — разные параметры** — волатильные бумаги (технологии, крипто) требуют других настроек, чем голубые фишки

### Эвристики для российского рынка

| Горизонт | MA Short / MA Long | RSI Period | Интервал свечей |
|---|---|---|---|
| Внутридневной (скальпинг) | 5 / 13 | 7 | 1–5 мин |
| Краткосрочный (1–5 дней) | 9 / 21 | 14 | 1 час |
| Среднесрочный (недели) | 20 / 50 | 14 | Дневные |
| Долгосрочный (месяцы) | 50 / 200 | 21 | Недельные |

> Текущая реализация опрашивает **последнюю цену** (`get_last_prices`), а не свечи. Это близко к тиковым данным. Для использования на свечах перепишите `_get_last_price` на опрос последней закрытой свечи (`get_candles`).

### Тест на исторических данных (ручной)

```python
from decimal import Decimal
from strategies import MACrossoverStrategy, RSIStrategy

prices = [Decimal(str(p)) for p in [100, 102, 101, 105, 108, 107, 110, ...]]

ma = MACrossoverStrategy("TEST", short_period=9, long_period=21)
rsi = RSIStrategy("TEST", period=14)

for price in prices:
    s1 = ma.update(price)
    s2 = rsi.update(price)
    if s1: print(f"MA: {s1.type.value} @ {price} — {s1.reason}")
    if s2: print(f"RSI: {s2.type.value} @ {price} — {s2.reason}")
```
